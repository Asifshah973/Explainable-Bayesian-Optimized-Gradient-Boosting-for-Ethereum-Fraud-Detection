# OT-LGBM: Optuna-tuned LightGBM for Blockchain Fraud Detection

Code for detecting fraudulent Ethereum accounts from transaction-level features using a
LightGBM classifier tuned with Optuna (TPE), with a **leakage-free evaluation protocol**.

## Protocol (summary)

| Stage | What is fitted | On which data |
|---|---|---|
| Median imputation, standardisation (Eq. 6) | per-feature median, μ, σ | training part of each fit only |
| SMOTE | synthetic minority samples | training part of each fit only, after the split |
| Hyper-parameter tuning | Optuna TPE, 5-fold stratified CV (ROC-AUC) | 80 % training portion only |
| Early stopping | validation split | carved out of the training portion |
| Decision threshold | fixed at 0.5 | not tuned |
| Final evaluation | one-shot | 20 % held-out test set |

Step-by-step description: [`docs/ALGORITHM.md`](docs/ALGORITHM.md).

## Project layout

```
src/otlgbm/
  config.py     settings (seed, split, folds, trials)
  data.py       loading + stratified split
  pipeline.py   imputer -> scaler -> SMOTE (fitted on training data only)
  tuning.py     Optuna search, grid-search comparison, convergence plot
  models.py     final OT-LGBM + baseline classifiers
  metrics.py    metrics, exact McNemar, ROC/PR figure
  explain.py    SHAP importance, inference latency
  cli.py        command line interface
tests/          unit + smoke tests
docs/           Algorithm 1
```

## Install

```bash
git clone https://github.com/<your-username>/blockchain-fraud-otlgbm.git
cd blockchain-fraud-otlgbm
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e .[dev]
```

## Data

Put `transaction_dataset.csv` in `data/` (see [`data/README.md`](data/README.md)).

## Run

```bash
# everything (tune -> train -> evaluate -> baselines -> grid -> crossval -> explain)
python -m otlgbm.cli all --data data/transaction_dataset.csv

# or step by step
python -m otlgbm.cli tune      --n-trials 100
python -m otlgbm.cli train
python -m otlgbm.cli evaluate
python -m otlgbm.cli baselines
python -m otlgbm.cli grid
python -m otlgbm.cli crossval
python -m otlgbm.cli explain
```

Useful flags: `--seed 42`, `--n-trials 100`, `--no-smote` (class weighting instead of SMOTE),
`--drop-duplicates`, `--out results`, `--models models`.

## Outputs (`results/`)

| File | Content |
|---|---|
| `best_params.json`, `optuna_trials.csv`, `optuna_convergence.png` | tuning (real trial values) |
| `metrics.json`, `confusion_matrix.csv` | held-out test metrics |
| `roc_pr_curve.png`, `test_scores.csv` | ROC / PR curves from actual predictions |
| `baselines.csv`, `mcnemar.csv` | model comparison + exact McNemar tests |
| `grid_vs_optuna.json` | grid search vs Optuna (same CV, same test set) |
| `crossval_10fold*.csv`, `crossval_split_ratios.csv` | robustness analyses |
| `shap_importance.csv/.png`, `shap_summary.png`, `latency.json` | explainability and speed |

All numbers and figures are generated by running the code; none are hard-coded.
Results are not committed — run the pipeline to reproduce them.

## Limitations

* The 10-fold and split-ratio analyses reuse hyper-parameters selected on the 80:20 split, so they are not fully independent of the tuning split.
* Exact duplicate rows in the raw data can cross the train/test boundary; use `--drop-duplicates` to check sensitivity.
